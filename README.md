# Актион Ассист - Виртуальный помощник технической поддержки

> **Кейс 2 «Помоги мне» · Хакатон · Команда: [#SWAG]**
> 
> **Развёрнутый MVP:** [http://159.194.247.71]

Из представленных кейсов на Хакатоне мы выбрали второй, так как он больше нам понравился своей актуальной проблемой. Все мы писали в техподдержку и ждали ответа на вопрос, который решается одной инструкцией. Пользователь хочет получить решение быстро и с минимальными усилиями, без лишних действий и повторных объяснений. Специалист поддержки хочет перестать тратить время на типовые вопросы и заниматься действительно сложными случаями. Так появилось решение создать виртуального ассистента, который понимает суть обращения, определяет категорию, задаёт только действительно необходимые уточняющие вопросы, выдаёт пошаговую инструкцию, а если помочь не удалось - передаёт обращение человеку вместе с полной историей диагностики.

**Актион Ассист** — это виртуальный помощник первой линии технической поддержки, который самостоятельно принимает обращения пользователей на естественном языке, определяет категорию проблемы, проводит диагностику по ветвящимся сценариям и выдаёт пошаговые инструкции для решения. Если стандартные шаги не помогают или ситуация нестандартная, ассистент бесшовно передаёт обращение живому специалисту вместе с полной карточкой диагностики — категорией, ответами пользователя и уже выполненными шагами — чтобы сотрудник не тратил время на повторный сбор информации.

**Главная цель решения, в соответствии с бизнес-задачей кейса:** пользователь получает решение своей проблемы максимально быстро и с минимальным количеством действий.

## Описание решения

**Актион Ассист** автоматизирует все этапы обработки проблем. Система действует как полноценный специалист поддержки:

1. **Принимает обращение** — пользователь описывает проблему в свободной форме через чат-интерфейс.
2. **Классифицирует** — словарный алгоритм (`classifier.py`) сопоставляет текст с ключевыми словами 7 категорий каталога услуг и вычисляет числовой показатель уверенности (от 0 до 1).
3. **Уточняет** — если уверенность ниже порога (0.6), бот предлагает пользователю выбрать категорию кнопками. Если уверенность достаточна — переходит к диагностике, задавая только те вопросы, которые действительно нужны для сужения круга причин.
4. **Решает** — находит подходящий сценарий в базе знаний (`knowledge_items.json`) и выдаёт пронумерованную пошаговую инструкцию. Если первые шаги не помогли, автоматически предлагает альтернативные (`alt_steps`).
5. **Завершает или эскалирует** — при успехе закрывает тикет и запрашивает оценку. При неудаче формирует JSON-карточку с полной историей диагностики и передаёт специалисту.

## Описание основного сценария

Полный пользовательский путь от начала до результата:

### Шаг 1 · Выбор роли для входа
Пользователь открывает приложение и видит окно с предложением выбрать, кем он является: специалист поддержки или пользователь - сотрудник. При выборе специалиста следует ввести код, который отображается в виде подсказки, для сотрудника вводить пароль не надо. 

### Шаг 2 · Обращение
Пользователь открывает приложение и описывает проблему своими словами в поле ввода (например, *«Не могу войти в Актион 360»*). Также доступны быстрые кнопки с типичными проблемами для моментального старта.

### Шаг 3 · Классификация
Ассистент анализирует текст обращения с помощью словарного классификатора. Каждой из 7 категорий сопоставлен набор ключевых слов. Система подсчитывает совпадения, выбирает наиболее подходящую категорию и рассчитывает уверенность по формуле: `confidence = min(0.97, 0.55 + 0.12 × количество_совпадений)`.

- Если **уверенность ≥ 60%** — бот показывает определённую категорию и переходит к диагностике.
- Если **уверенность < 60%** или категория не определена — бот просит пользователя выбрать категорию из предложенных кнопок.

### Шаг 4 · Уточняющие вопросы
Система находит подходящий сценарий в базе знаний по категории и ключевым словам, затем задаёт уточняющие вопросы **строго по сценарию** — только те, ответы на которые действительно необходимы для решения. Например:

> *«Что именно происходит при попытке входа?»*
> Кнопки: [Неверный пароль] [Страница не загружается] [Не приходит письмо] [Другое]

Если пользователь отвечает свободным текстом вместо нажатия кнопки, система сначала пытается сопоставить ответ с вариантами через `difflib.get_close_matches` (нечёткое сравнение). Если это не удаётся, подключается (`llm.py`) для семантической интерпретации ответа.

### Шаг 5 · Решение проблемы
На основе ответов пользователя система выбирает ветку сценария и выдаёт пронумерованную пошаговую инструкцию. Например:

> 1. Проверьте раскладку клавиатуры и CapsLock
> 2. Нажмите «Забыли пароль?» на странице входа
> 3. Проверьте почту и папку «Спам»
> 4. Задайте новый пароль и войдите снова

Если пользователь сообщает, что шаги **не помогли**, система автоматически предлагает **альтернативные шаги** (`alt_steps`), если они предусмотрены сценарием.

### Шаг 6 · Завершение обращения
В конце диалога пользователь всегда понимает:
- **Какая проблема была определена** — категория и название сценария отображаются в каждом сообщении бота.
- **Удалось ли её решить** — при подтверждении успеха тикет закрывается со статусом `resolved`.
- **Нужно ли обратиться к специалисту** — если шаги не помогли, бот предлагает эскалацию с кнопкой «Передать специалисту».
- **Что делать дальше** — после успешного решения бот запрашивает оценку (1–5 звёзд); после эскалации сообщает номер тикета и объясняет, что специалист изучит карточку диагностики.

## Дополнительный функционал

Помимо пяти обязательных этапов основного сценария, в системе реализованы следующие дополнительные возможности:

### 1. Передача обращения специалисту с карточкой диагностики
При эскалации система автоматически формирует структурированную JSON-карточку, содержащую:
- Определённую категорию и название проблемы
- Исходное сообщение пользователя
- Все ответы на уточняющие вопросы
- Список уже выполненных шагов
- Уровень уверенности ИИ в классификации
- Причину эскалации

Специалист получает полную картину без необходимости заново опрашивать пользователя.

### 2. Кабинет специалиста (Support Queue)
Защищённая панель, доступная по токену (заголовок `x-specialist-token`). Специалист видит очередь всех эскалированных обращений с их статусами и уровнем уверенности ИИ. 

### 3. Система обратной связи (Feedback)
После успешного решения пользователь оценивает качество помощи по 5-балльной шкале. **Авто-эскалация при низкой оценке:** если пользователь ставит 1 или 2 звезды, система автоматически меняет статус тикета на `escalated` и добавляет комментарий для ручного разбора специалистом.

### 4. Поиск по базе знаний
Отдельный интерфейс в боковой панели с поиском в реальном времени. Результаты обновляются по мере ввода (минимум 3 символа). Поиск ведётся по названиям сценариев и ключевым словам.

### 5. История обращений
Пользователь может открыть боковую панель «История» и просмотреть список всех своих прошлых обращений с указанием категории и текущего статуса.

### 6. Отображение категории и уверенности
Каждое сообщение ассистента сопровождается бейджем, показывающим определённую категорию и процент уверенности (например: *«Категория: Доступы · уверенность 79%»*). Пользователь всегда понимает, как система интерпретировала его проблему.

### 7. Альтернативные решения
Если основные шаги не помогли, система автоматически предлагает альтернативный набор инструкций (`alt_steps`) без необходимости начинать диагностику заново.

### 8. Защита от некорректного ввода
Система распознаёт бессмысленные сообщения (менее 3 символов, отсутствие букв), отказы («не хочу», «не буду») и переключения темы. При обнаружении смены проблемы бот предлагает оформить отдельное обращение, не теряя контекст текущего.

## Ограничения MVP и план развития

В соответствии с требованиями к README, ниже описаны осознанные архитектурные компромиссы, принятые для обеспечения работоспособности MVP в рамках хакатона, а также план их устранения в production-версии.

### 1. Классификация на ключевых словах
- **Что сделано:** Словарный алгоритм (`classifier.py`) с 7 категориями и ~60 ключевыми словами. Работает локально, без сетевых задержек.
- **Почему так:** Обеспечивает мгновенный отклик (< 1 мс) и полную работоспособность без интернета. Для MVP с 13 сценариями этого достаточно.
- **План на v2.0:** Замена на NLP-модель с fine-tuning на размеченных обращениях для обработки сложных формулировок и опечаток.

### 2. Статичная база знаний (JSON)
- **Что сделано:** 13 сценариев с ветвлениями хранятся в файле `knowledge_items.json`.
- **Почему так:** Позволило быстро реализовать гибкую логику ветвления (steps → scenario → escalate) без разработки отдельного сервиса управления знаниями.
- **План на v2.0:** Админ-панель с визуальным редактором сценариев для специалистов поддержки. Хранение в БД с версионированием.

### 3. Локальная база данных (SQLite)
- **Что сделано:** Файловая БД `assist.db` создаётся автоматически при первом запуске, не требует установки сервера.
- **Почему так:** Zero-config развёртывание — любой член жюри может запустить проект одной командой без настройки PostgreSQL, Docker или миграций.
- **План на v2.0:** Миграция на PostgreSQL для поддержки конкурентной записи, пула соединений и масштабирования.

### 4. Имитация эскалации
- **Что сделано:** Передача специалисту реализована как смена статуса тикета в БД. Карточка диагностики формируется и отображается в кабинете специалиста.
- **Почему так:** Прямая интеграция с внешними системами (Jira, Zendesk) требует API-ключей, настройки окружения и выходит за рамки MVP.
- **План на v2.0:** Интеграция с Jira/Zendesk через webhook, уведомления в Telegram/Slack для специалистов.

## Сильные стороны решения

1. **Полный пользовательский путь без критических ошибок** — от первого сообщения до закрытия тикета или эскалации. Каждый сценарий протестирован на всех ветках.
2. **Минимум вопросов пользователю** — система задаёт только те вопросы, которые предусмотрены сценарием и действительно сужают круг причин.
3. **Контекст не теряется** — при передаче специалисту карточка содержит всю историю: исходное сообщение, категорию, ответы на вопросы и выполненные шаги.
4. **Устойчивость к некорректному вводу** — система обрабатывает бессмыслицу, отказы, смену темы и повторные попытки, не «зависая» в неопределённом состоянии.
5. **Один процесс для запуска** — фронтенд раздаётся самим FastAPI, что исключает проблемы с CORS и упрощает развёртывание.
6. **Живой, эмпатичный интерфейс** — маскот «Акти» меняет анимации в зависимости от контекста (думает, радуется, грустит), что снижает стресс пользователя при обращении в поддержку.

### API-эндпоинты

| Метод | Путь | Описание |
|:---:|---|---|
| `POST` | `/api/chat` | Основной диалог. Принимает `{ticket_id, message}`, возвращает следующий шаг сценария |
| `GET` | `/api/tickets` | Список всех тикетов |
| `GET` | `/api/tickets/{id}` | Детали тикета с историей сообщений и выполненными шагами |
| `POST` | `/api/tickets/{id}/resolve` | Закрытие тикета (проблема решена) |
| `POST` | `/api/tickets/{id}/escalate` | Эскалация тикета специалисту с формированием карточки диагностики |
| `POST` | `/api/feedback` | Оценка (1–5 звёзд). При оценке ≤ 2 — автоматическая эскалация |
| `GET` | `/api/knowledge/search?q=` | Поиск по базе знаний (параметр `q` — поисковый запрос) |
| `GET` | `/api/support/queue_protected` | Очередь эскалированных тикетов. Требует заголовок `x-specialist-token` |

### Пользовательский интерфейс
Фронтенд разработан с фокусом на удобство и понятность для конечного пользователя:
Минимализм и чистота — один экран, без лишних меню и переходов. Всё взаимодействие происходит в чате.
Быстрые кнопки — вместо принудительного ввода текста пользователь может выбирать ответы нажатием кнопок, что ускоряет диалог.
Визуальная обратная связь — маскот «Акти» (SVG-анимация) меняет эмоции в реальном времени: думает при обработке (thinking), радуется при успехе (success), грустит при эскалации (escalation). Это делает взаимодействие человечным и снижает тревожность.
Параллакс-эффект — маскот в шапке следит за курсором мыши, создавая ощущение живого присутствия.
Адаптивность — интерфейс корректно отображается на мобильных устройствах, планшетах и десктопах.
Доступность — поддержка prefers-reduced-motion для пользователей, чувствительных к анимации.
