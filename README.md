# Датасет для кейса 2
## Описание решения: 
Система представляет собой ассистента, который принимает обращения пользователей на естественном языке, определяет проблему и проводит 
пользователя по ветке диагностического сценария. Если стандартные решения помогают, обращение закрывается автоматически. 
Если проблема нестандартная или шаги не сработали, ассистент передаёт обращение специалисту, передавая ему полную карточку диагностики
(категорию, ответы пользователя и выполненные шаги), чтобы специалист не тратил время на первичный сбор информации.

## Описание основного сценария
Обращение: Пользователь описывает проблему своими словами (например, "Не могу войти в Актион 360" или "Не приходит письмо").
Классификация: Ассистент анализирует текст, определяет категорию проблемы (Доступы, Почта, ПО, Wi-Fi и т.д.) и оценивает уверенность.
Уточнение (если нужно): Если уверенность низкая, бот просит выбрать категорию из предложенных кнопок.
Диагностика: Ассистент задает уточняющие вопросы согласно сценарию из базы знаний, чтобы сузить круг причин.
Решение: Бот выдает пошаговую инструкцию для решения проблемы.
Завершение или Эскалация:
Успех: Пользователь подтверждает, что проблема решена. Бот просит оценить качество помощи (1-5 звезд) и закрывает тикет.
Неудача: Если шаги не помогли, бот предлагает передать обращение специалисту. При согласии создается карточка эскалации.

## Используемые технологии
Backend:
Python — язык программирования.
FastAPI — современный высокопроизводительный фреймворк для создания API.
SQLite — легковесная реляционная база данных для хранения тикетов, сообщений и обратной связи.
Pydantic — валидация данных и управление настройками через модели.
Frontend:
HTML5 / CSS3 — адаптивная и чистая верстка в стиле минимализма.
Vanilla JavaScript (ES6+) — логика чата, работа с DOM и отправка асинхронных запросов (Fetch API) без использования тяжелых фреймворков.
Данные:
JSON — хранение базы знаний и диагностических сценариев.

## Ограничения MVP (Минимально жизнеспособного продукта)
Текущая версия имеет следующие ограничения:
Классификация на ключевых словах: Вместо полноценной NLP/LLM модели (например, GPT или BERT) используется алгоритм на основе словаря ключевых слов. Это работает быстро, 
но может ошибаться на сложных или опечатанных запросах. 
Статичная база знаний: Сценарии и статьи хранятся в JSON-файле. Для добавления новых решений требуется ручное редактирование файла (без админ-панели).
Локальная база данных: SQLite отлично подходит для MVP, но для продакшена с высокой нагрузкой потребуется переход на PostgreSQL.
Имитация эскалации: Передача специалисту реализована как создание карточки тикета в системе. Прямой интеграции с Jira, Zendesk или Telegram специалиста в MVP не предусмотрено.

## Дополнительный функционал
Помимо базового чата, в системе реализованы полезные инструменты:
Система обратной связи (Feedback): Пользователи могут оценить работу бота по 5-балльной шкале после решения проблемы.
Поиск по базе знаний: Отдельный интерфейс для быстрого поиска инструкций и статей по ключевым словам.
Кабинет специалиста (Support Queue): Панель, где сотрудники техподдержки могут видеть очередь эскалированных тикетов, их статус и уверенность ИИ.
История обращений: Пользователь может посмотреть список своих прошлых тикетов и их статусы.
Swagger UI: Полностью автоматизированная интерактивная документация API для удобной отладки и интеграции.
