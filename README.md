
# Акти Ассист — Виртуальный помощник технической поддержки

> **Кейс 2 «Помоги мне» · Хакатон · Команда: [#SWAG], Петрова Алина, Неустроева Алина, Ракитянская Алиса, Рыжкова Ярослава, Заикина Влада из группы 8И51Т, 8И52Т**
> 
> **Развёрнутый MVP:** [http://159.194.247.71]

Из представленных кейсов на Хакатоне мы выбрали второй, так как он больше нам понравился своей актуальной проблемой. Все мы писали в техподдержку и ждали ответа на вопрос, который решается одной инструкцией. Пользователь хочет получить решение быстро и с минимальными усилиями, без лишних действий и повторных объяснений. Специалист поддержки хочет перестать тратить время на типовые вопросы и заниматься действительно сложными случаями. Так появилось решение создать виртуального ассистента, который понимает суть обращения, определяет категорию, задаёт только действительно необходимые уточняющие вопросы, выдаёт пошаговую инструкцию, а если помочь не удалось — передаёт обращение человеку вместе с полной историей диагностики.

Акти — это виртуальный помощник первой линии технической поддержки, воплощённый в образе красной искры. Маскот отражает саму суть бренда «Актион»: стремительный старт, энергию и мгновенную реакцию на проблему пользователя. Если стандартные шаги не помогают или ситуация нестандартная, ассистент бесшовно передаёт обращение живому специалисту вместе с историей диалога — категорией, ответами пользователя и уже выполненными шагами — чтобы сотрудник не тратил время на повторный сбор информации.

**Главная цель решения, в соответствии с бизнес-задачей кейса:** пользователь получает решение своей проблемы максимально быстро и с минимальным количеством действий.

## Описание решения

**Актион Ассист** автоматизирует все этапы обработки проблем. Система действует как полноценный специалист поддержки:

1. **Принимает обращение** — пользователь описывает проблему в свободной форме через чат-интерфейс.
2. **Классифицирует** — словарный алгоритм (`classifier.py`) сопоставляет текст с ключевыми словами 7 категорий каталога услуг и вычисляет числовой показатель уверенности (от 0 до 1).
3. **Уточняет** — если уверенность ниже порога (0.6), бот предлагает пользователю выбрать категорию кнопками. Если уверенность достаточна — переходит к диагностике, задавая только те вопросы, которые действительно нужны для сужения круга причин.
4. **Решает** — находит подходящий сценарий в базе знаний (`knowledge_items.json`) и выдаёт пронумерованную пошаговую инструкцию. Если первые шаги не помогли, автоматически предлагает альтернативные (`alt_steps`).
5. **Завершает или эскалирует** — при успехе закрывает тикет и запрашивает оценку. При неудаче формирует карточку с историей диагностики и передаёт обращение специалисту.

### Архитектура

```text
Frontend (index.html)
  |  HTTP/JSON
  |  /api/chat, /api/tickets, /api/feedback,
  |  /api/knowledge/search, /api/support/*
  v
Backend (FastAPI + Python)
  |
  |-- classifier.py  # категории и уверенность
  |-- knowledge.py   # 23 сценария, поиск, ветвления
  |-- llm.py         # опциональный YandexGPT
  |-- db.py          # SQLite CRUD
  |-- auth.py        # задел под будущую авторизацию
  v
SQLite (backend/data/assist.db)
  tickets / messages / feedback
```

Фронтенд полностью статичен (один HTML-файл) и раздаётся самим FastAPI через `StaticFiles`, что позволяет развернуть всё приложение одним процессом без отдельного веб-сервера.

## Описание основного сценария

Полный пользовательский путь от начала до результата:

### Шаг 1 · Выбор роли для входа

Пользователь открывает приложение и видит окно с предложением выбрать роль:

- **Я пользователь — сотрудник** — вход без пароля.
- **Я специалист поддержки** — вход по демо-коду специалиста. В интерфейсе есть подсказка: код `hacaton`.

### Шаг 2 · Обращение

Пользователь открывает приложение и описывает проблему своими словами в поле ввода (например, *«Не могу войти в Актион 360»*). Также доступны быстрые кнопки с типичными проблемами для моментального старта.

### Шаг 3 · Классификация

Ассистент анализирует текст обращения с помощью словарного классификатора. Каждой из 7 категорий сопоставлен набор ключевых слов. Система подсчитывает совпадения, выбирает наиболее подходящую категорию и рассчитывает уверенность по формуле:

```text
confidence = min(0.97, 0.55 + 0.12 × количество_совпадений)
```

- Если **уверенность ≥ 60%** — бот показывает определённую категорию и переходит к диагностике.
- Если **уверенность < 60%** или категория не определена — бот просит пользователя выбрать категорию из предложенных кнопок.

Дополнительно система отфильтровывает слишком короткие или бессмысленные сообщения, а также проверяет, похоже ли сообщение на реальную техническую проблему.

### Шаг 4 · Уточняющие вопросы

Система находит подходящий сценарий в базе знаний по категории и ключевым словам, затем задаёт уточняющие вопросы **строго по сценарию** — только те, ответы на которые действительно необходимы для решения. Например:

> *«Что именно происходит при попытке входа?»*  
> Кнопки: [Неверный пароль] [Страница не загружается] [Не приходит письмо] [Другое]

Если пользователь отвечает свободным текстом вместо нажатия кнопки, система сначала пытается сопоставить ответ с вариантами через `difflib.get_close_matches` (нечёткое сравнение). Если это не удаётся и заданы ключи Yandex Cloud, подключается модуль `llm.py` для семантической интерпретации ответа.

### Шаг 5 · Решение проблемы

На основе ответов пользователя система выбирает ветку сценария и выдаёт пронумерованную пошаговую инструкцию. Например:

> 1. Проверьте раскладку клавиатуры и CapsLock  
> 2. Нажмите «Забыли пароль?» на странице входа  
> 3. Проверьте почту и папку «Спам»  
> 4. Задайте новый пароль и войдите снова

Если пользователь сообщает, что шаги **не помогли**, система автоматически предлагает **альтернативные шаги** (`alt_steps`), если они предусмотрены сценарием.

### Шаг 6 · Завершение обращения

В конце диалога пользователь всегда понимает:

- **Какая проблема была определена** — категория и уверенность отображаются в сообщениях бота.
- **Удалось ли её решить** — при подтверждении успеха тикет закрывается со статусом `resolved`.
- **Нужно ли обратиться к специалисту** — если шаги не помогли, бот предлагает эскалацию с кнопкой «Передать специалисту».
- **Что делать дальше** — после успешного решения бот запрашивает оценку (1–5 звёзд); после эскалации сообщает номер тикета и объясняет, что специалист изучит историю диагностики.

## Дополнительный функционал

Помимо пяти обязательных этапов основного сценария, в системе реализованы следующие дополнительные возможности:

### 1. Передача обращения специалисту с карточкой диагностики

При эскалации система автоматически формирует структурированную карточку, содержащую:

- Определённую категорию и название проблемы
- Исходное сообщение пользователя
- Все ответы на уточняющие вопросы
- Список уже выполненных шагов
- Уровень уверенности ИИ в классификации
- Причину эскалации

Специалист получает полную историю диалога без необходимости заново опрашивать пользователя.

### 2. Кабинет специалиста (Support Queue)

Отдельный режим, доступный через экран выбора роли. Специалист вводит демо-код доступа. В текущем MVP используется код `hacaton`, который отображается в подсказке на экране входа.

Специалист видит очередь всех эскалированных обращений с их статусами, уровнем уверенности ИИ и временем ожидания. Доступны действия:

- взять тикет в работу;
- открыть диалог;
- ответить пользователю;
- пометить обращение как решённое специалистом;
- посмотреть аналитику за день или неделю;
- открыть архив закрытых обращений;
- удалить закрытые обращения или очистить архив.

Специалист взаимодействует с защищёнными эндпоинтами через заголовок:

```http
x-support-code: hacaton
```

### 3. Система обратной связи (Feedback)

После успешного решения пользователь оценивает качество помощи по 5-балльной шкале.

**Авто-эскалация при низкой оценке:** если пользователь ставит 1 или 2 звезды, система автоматически меняет статус тикета на `escalated` и добавляет комментарий для ручного разбора специалистом.

### 4. Поиск по базе знаний

Отдельный интерфейс в боковой панели с поиском в реальном времени. Результаты обновляются по мере ввода (минимум 3 символа). Поиск ведётся по названиям сценариев и ключевым словам.

### 5. История обращений

Пользователь может открыть боковую панель «История» и просмотреть список своих прошлых обращений с указанием категории, статуса и времени создания.

История привязывается к локальному идентификатору клиента, который передаётся в заголовке:

```http
X-Client-Id: <локальный идентификатор браузера>
```

### 6. Отображение категории и уверенности

Сообщения ассистента сопровождаются бейджем, показывающим определённую категорию и процент уверенности (например: *«Категория: Доступы · уверенность 79%»*). Пользователь всегда понимает, как система интерпретировала его проблему.

### 7. Альтернативные решения

Если основные шаги не помогли, система автоматически предлагает альтернативный набор инструкций (`alt_steps`) без необходимости начинать диагностику заново.

### 8. Защита от некорректного ввода

Система распознаёт бессмысленные сообщения (менее 3 символов, отсутствие букв), отказы («не хочу», «не буду») и переключения темы. При обнаружении смены проблемы бот предлагает оформить отдельное обращение, не теряя контекст текущего.

### 9. Ответ специалиста в пользовательском чате

После эскалации пользователь видит, что обращение передано специалисту. Если специалист отвечает из кабинета, ответ появляется в пользовательском чате за счёт периодического опроса истории сообщений.

## Ограничения MVP и план развития

Ниже описаны осознанные архитектурные компромиссы, принятые для обеспечения работоспособности MVP в рамках хакатона, а также краткий план их устранения в следующей версии.

### 1. Классификация на ключевых словах

- **Что сделано:** Словарный алгоритм (`classifier.py`) с 7 категориями и набором ключевых слов. Работает локально, без сетевых задержек.
- **Почему так:** Обеспечивает мгновенный отклик и полную работоспособность без интернета.
- **План на следующую версию:** Замена на векторный поиск или NLP-модель для лучшего понимания опечаток и нестандартных формулировок.

### 2. Статичная база знаний (JSON)

- **Что сделано:** 23 сценария с ветвлениями хранятся в файле `knowledge_items.json`.
- **Почему так:** Позволило быстро реализовать гибкую логику ветвления (вопросы → шаги → эскалация) без разработки отдельного сервиса управления знаниями.
- **План на следующую версию:** Админ-панель с визуальным редактором сценариев и хранение базы знаний в БД.

### 3. Локальная база данных (SQLite)

- **Что сделано:** Файловая БД `assist.db` создаётся автоматически при первом запуске, не требует установки сервера.
- **Почему так:** Zero-config развёртывание — проект можно запустить одной командой без настройки внешней БД.
- **План на следующую версию:** Миграция на PostgreSQL для конкурентной записи, пула соединений и масштабирования.

### 4. Упрощённая эскалация и авторизация

- **Что сделано:** Передача специалисту реализована как смена статуса тикета в БД и работа специалиста через отдельный интерфейс с демо-кодом. Модуль `auth.py` подготовлен как задел для дальнейшей полноценной авторизации.
- **Почему так:** Для демонстрации продукта на хакатоне достаточно упрощённого входа и внутренней очереди.
- **План на следующую версию:** Полноценная авторизация, роли, права доступа, интеграция с внешней helpdesk-системой и уведомления специалистов.

## Сильные стороны решения

1. **Полный пользовательский путь без критических ошибок** — от первого сообщения до закрытия тикета или эскалации.
2. **Минимум вопросов пользователю** — система задаёт только те вопросы, которые предусмотрены сценарием и действительно сужают круг причин.
3. **Контекст не теряется** — при передаче специалисту сохраняется вся история: исходное сообщение, категория, ответы на вопросы и выполненные шаги.
4. **Устойчивость к некорректному вводу** — система обрабатывает бессмыслицу, отказы, смену темы и повторные попытки, не «зависая» в неопределённом состоянии.
5. **Один процесс для запуска** — фронтенд раздаётся самим FastAPI, что исключает проблемы с CORS и упрощает развёртывание.
6. **Живой, эмпатичный интерфейс** — маскот «Акти» меняет анимации в зависимости от контекста (думает, радуется, грустит), что снижает стресс пользователя при обращении в поддержку.

## Использование ИИ в разработке

В соответствии с правилами хакатона, сообщаем об использовании ИИ-инструментов:

| Этап | Инструмент | Задача |
|---|---|---|
| Генерация кода | ИИ-ассистенты (например, Qwen / GitHub Copilot) | Написание шаблонного кода FastAPI-роутов, Pydantic-схем, CSS-анимаций |
| Работа с текстом | ИИ-ассистенты | Структурирование JSON-файла базы знаний, формулировка текстов подсказок и вопросов для пользователя |
| Создание интерфейса | ИИ-ассистенты | Генерация SVG-графики маскота «Акти», помощь с CSS-переменными и `@keyframes` |
| Анализ данных | ИИ-ассистенты | Подбор ключевых слов для классификатора на основе типичных обращений |

**Интеграция LLM в продукт:** В самом приложении реализован опциональный вызов **YandexGPT API** (`backend/app/llm.py`) для двух задач:

1. **Интерпретация свободных ответов** — если пользователь отвечает текстом вместо нажатия кнопки, LLM сопоставляет ответ с предложенными вариантами.
2. **Фильтрация нерелевантных сообщений** — определение, описывает ли сообщение техническую проблему или является шуткой/бессмыслицей.

Если переменные окружения `YC_API_KEY` и `YC_FOLDER_ID` не заданы, система продолжает работать без LLM, используя правила, нечёткое сопоставление и сценарии базы знаний.

## Инструкция по запуску

### 1. Клонирование репозитория

```bash
git clone https://github.com/aall6-d/hahatonz
cd hahatonz
```

### 2. Создание виртуального окружения и установка зависимостей

**Windows:**

```bash
python -m venv venv
venv\Scripts\activate
pip install -r backend/requirements.txt
```

**macOS / Linux:**

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r backend/requirements.txt
```

### 3. Запуск сервера

```bash
cd backend
uvicorn app.main:app --reload
```

Приложение доступно по адресу:

```text
http://127.0.0.1:8000
```

### 4. Опциональные переменные окружения

По умолчанию приложение работает без дополнительных настроек. При необходимости можно задать:

```text
DB_PATH        — путь к файлу базы данных (по умолчанию: backend/data/assist.db)
SUPPORT_CODE   — код специалиста (по умолчанию: hacaton)
YC_API_KEY     — API-ключ Yandex Cloud для включения LLM-функций
YC_FOLDER_ID   — идентификатор каталога Yandex Cloud для включения LLM-функций
```

### 5. Доступ к разделам

- **Чат пользователя:** `http://127.0.0.1:8000`
- **Swagger UI (API-документация):** `http://127.0.0.1:8000/docs`
- **Кабинет специалиста:** выбирается на стартовом экране роль «Я специалист поддержки», демо-код: `hacaton`

## Пользовательский интерфейс

Фронтенд разработан с фокусом на удобство и понятность для конечного пользователя:

- **Минимализм и чистота** — один экран, без лишних меню и переходов. Всё взаимодействие происходит в чате.
- **Быстрые кнопки** — вместо принудительного ввода текста пользователь может выбирать ответы нажатием кнопок, что ускоряет диалог.
- **Визуальная обратная связь** — маскот «Акти» (SVG-анимация) меняет эмоции в реальном времени: думает при обработке (`thinking`), радуется при успехе (`success`), грустит при эскалации (`escalation`). Это делает взаимодействие человечным и снижает тревожность.
- **Параллакс-эффект** — маскот в шапке следит за курсором мыши, создавая ощущение живого присутствия.
- **Адаптивность** — интерфейс корректно отображается на мобильных устройствах, планшетах и десктопах.
- **Доступность** — поддержка `prefers-reduced-motion` для пользователей, чувствительных к анимации.
